## Гипотезы на проверку

| Гипотеза | Как проверяем | Принимаем, если |
|---|---|---|
| «Добавить канал рядом с МП» работает лучше, чем «уйти с МП» | две версии первого экрана, одинаковый трафик | квалифицированных заявок больше на 30%+ |
| Открытые цены на лендинге повышают качество лидов | сравнить с периодом «цена по запросу» | доля диагностик → договор выше |
| Платный Этап 0 отсеивает незрелых и не отпугивает зрелых | 10–20 обращений | 50%+ купивших этап 0 переходят в пакет |
| Селлеру важнее общие остатки, чем дизайн | вопрос на диагностике «что важнее» | 2 из 3 выбирают остатки |
| A2 (бренд с визиткой) отвечает чаще A1 | 40 + 40 касаний | ответов A2 в 1,5 раза больше |
| Страх «пустого сайта» — главный барьер | разбор 10–15 отказов | упоминается в 40%+ отказов |

## Метрики системы (раз в неделю, таблица лидов)

```
касания → ответы → диагностики → этап 0 / смета → договор → запуск → разбор 30 дней → повторный заказ
```

Плюс: среднее время ответа на лид · средний чек · факт часов / норма · срок от материалов до запуска · причины отказов (дословно).

## Правила итераций

1. Одна итерация — одно конкретное изменение с причиной (данные или найденное противоречие).
2. Нормы меняются только в `scripts/insales/works.mjs`, затем `node scripts/insales/build-docs.mjs` — цены в документах пересобираются. Цены пакетов в текстах (02, 06, 07, 08, 10) правятся вручную по `packages.md`.
3. Каждая итерация — запись в журнал выше: что было, что изменили, на каких данных.
4. Не переписывать блок без новых данных.
