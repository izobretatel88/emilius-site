# 03 · Конструктор услуги

Проект собирается из атомарных работ: **блок → работа → вариант → норма → зависимость → цена**. Полный перечень (100 работ, 17 блоков) с нормами, входом, результатом и рисками — `03-raboty.md` и `works.csv` (для Google Таблиц). Источник истины — `scripts/insales/works.mjs`.

## Как собрать проект

1. Заполнить бриф (`04-otsenka.md`) → получить JSON ответов.
2. `node scripts/insales/estimate.mjs бриф.json` → список работ, часы по ролям, цена, срок.
3. Если проект укладывается в границы пакета — продаём пакет по фиксированной цене + модули сверху.
4. Если не укладывается — продаём смету калькулятора как «ФИКС ±30%» (правило агентства).
5. Список работ из сметы = заказ к договору = задачи в Weeek. Один ID работы — одна задача с таймером.

## Порядок сборки и зависимости

```
D (этап 0) ─→ P (аккаунт, домен) ─→ T (тема) ─→ L (страницы)
                     │                 │
                     ├→ PAY, DLV (подавать заявки в банк и СДЭК в первый день: модерация 3–10 дней)
                     │
D06 структура ─→ C01–C03 ─→ C04/C05 или C06 или C07 или I1C2 ─→ C09–C14
                                          └→ IMS / IMP (после того как каталог стабилен)
P03 домен ─→ A (аналитика) ─→ S (SEO)
всё ─→ Q (тесты) ─→ R (передача, открытие)
```

Критический путь — **каталог** (качество данных клиента) и **эквайринг** (модерация банка). Остальное параллелится.

## Глубокие разделы

### Каталог — главный источник перерасхода

| Ситуация | Работы | Подводные камни | Как защищаемся |
|---|---|---|---|
| Таблица клиента в Excel | C04 → C05 → C09 | дубли, пустые цены, фото не по ссылкам | коэффициент `dirtyData`, шаблон таблицы выдаём до старта |
| Товары на WB/Ozon | C06 → C10 → C09 | на МП каждый размер — отдельная карточка; категории МП не совпадают с нашими; описания с SEO-мусором МП | склейка C10 по артикулу продавца; C12 по запросу |
| Старый сайт | C07 → S04 | парсер ломается; старые URL нужны для редиректов | выгрузка YML/CSV в приоритете, парсер — запасной |
| Товары в 1С | I1C2 → C09 | группы 1С ≠ категории сайта; характеристики 1С → варианты | сопоставление групп в D06 |
| Ничего нет | C08 | материалы приходят частями | отдельная оплата за товар, срок от даты получения материалов |

Пороговые объёмы: до 100 товаров — ручная проверка всего; до 1000 — выборка 30+; свыше 3000 — отдельная оценка, импорт пачками по 500.

Варианты: InSales хранит до 3 параметров варианта (размер, цвет, фасовка). Больше — коэффициент сложности, решение через свойства.

### Дизайн и изменение шаблона

- Уровень 0 (в пакетах): настройки темы — цвета, шрифты, блоки, порядок. Ноукод, без кода.
- Уровень 1: баннеры, иконки, графика (T05, DES).
- Уровень 2: точечные модификации (M01–M04) — разработчик, правки в отдельных файлах, чтобы обновление темы их не затёрло.
- Уровень 3: макеты (T09) + вёрстка по макету (M06) — это уже не «шаблон». Если M06 > 3 экранов — предлагаем кастомную разработку.

Правило: показываем клиенту демо выбранной темы **до** договора. Всё, чего нет в демо, — модификация с ценой.

### Оплата

Варианты: Т-Банк, ЮKassa, Сбер, CloudPayments; СБП; Долями/рассрочка — PAY2. Чеки 54-ФЗ — PAY3 обязательно. Клиент подаёт заявку в банк в день старта, мы готовим сайт к модерации (оферта, контакты, цены, доставка — банк проверяет их наличие). Тестовая оплата 1–10 ₽ с возвратом в Q01.

### Доставка

Минимум: СДЭК + Почта + самовывоз. Вес и габариты: если у товаров их нет, ставим значения по умолчанию по категории, иначе расчёт неверный. 3+ службы — через агрегатор (ApiShip) одной интеграцией. Своя курьерская — зоны (DLV2).

### 1С

1. **I1C1 аудит**: конфигурация (УТ 11, Розница, УНФ, Бухгалтерия — не подходит для обмена товарами), версия, кто 1С-специалист клиента.
2. Формат обмена: CommerceML (штатный), модуль обмена (Infostart, ~2 500 ₽ лицензия), или через МойСклад как прослойку.
3. Порядок: товары → цены → остатки → заказы → покупатели → тест.
4. Граница ответственности: настройка узла обмена **в 1С** делает специалист клиента или партнёр-1С. Мы — сторона InSales и тест. Без 1С-специалиста клиента модуль не продаём.
5. Тест: 10 циклов обмена без ошибок, заказ с сайта появился в 1С, статус вернулся.

### МойСклад

Штатная интеграция InSales ↔ МойСклад (лицензия в МойСклад ~5 000 ₽, платит клиент). Сопоставление по артикулу; если артикулы разные — сначала приводим их к одному виду. Остатки — выбрать склады. Заказы — в МойСклад, статусы обратно.

### Маркетплейсы

- Тариф «Комбо» обязателен для управления WB/Ozon/Я.Маркетом из InSales.
- Важно: остатки **FBO** (на складе площадки) не синхронизируются с сайтом — продаём с сайта только FBS/свой склад. Это объясняем на квалификации.
- Порядок: IMP1 подключение → IMP2 сопоставление карточек → IMP3 правила цен и остатков (наценка по каналу, резерв) → тест «продал на WB — уменьшилось на сайте».

### CRM

По умолчанию — встроенная CRM InSales (0 ч). Внешняя CRM — когда заказы уже ведут там. Граница: настраиваем передачу заказов и статусов, не строим воронки продаж.

### SEO

- Пакеты: S01 шаблоны мета, ЧПУ, robots, sitemap; Бизнес+ — S02 мета 15 страниц вручную.
- Опция S03 семантика — делается **до** D06, потому что меняет структуру категорий. Для локального бизнеса (сегмент C) — почти обязательна.
- Переезд (сегмент D) — S04 редиректы обязательны, иначе не берём проект.

### Аналитика

Метрика и Вебмастер — всегда на аккаунте клиента. Цели: заказ, корзина, клик в мессенджер, звонок. E-commerce — встроенная интеграция InSales, проверяем тестовым заказом, что выручка дошла до Метрики. UTM-схема (A05) — для каналов: Директ, VK, рассылка, вкладыш, соцсети.
