# 04 · Оценка проекта: квалификация, бриф, расчёт

Три уровня, от быстрого к точному:

1. **Квалификация** — 7 вопросов, 5 минут, в переписке или на первом созвоне. Итог: балл 0–14 и маршрут.
2. **Бриф** — 25 вопросов, клиент заполняет сам (форма) или PM на созвоне. Каждый ответ = поле JSON для калькулятора.
3. **Смета** — `node scripts/insales/estimate.mjs бриф.json`. Итог: работы, часы, цена, срок.

## 1. Квалификация лида (балл)

| # | Вопрос | 0 | 1 | 2 |
|---|---|---|---|---|
| Q1 | Где сейчас продаёте и сколько заказов в месяц? | не продаём | до 30 | 30+ |
| Q2 | Откуда придут первые покупатели сайта? | «из поиска как-нибудь» | соцсети/база до 1 000 человек | брендовый спрос, база 1 000+, офлайн-поток, бюджет на рекламу |
| Q3 | Сколько товаров и где они описаны? | нигде | таблица/МП до 1 000 | таблица/МП/1С, данные чистые |
| Q4 | Кто будет обрабатывать заказы? | «разберёмся» | владелец сам | есть сотрудник |
| Q5 | Бюджет на запуск? | до 50 тыс. | 50–120 тыс. | 120+ тыс. |
| Q6 | Когда нужен магазин и почему именно тогда? | «когда-нибудь» | в течение 3 мес. | есть событие и дата (сезон, вторая точка, новая марка) |
| Q7 | Кто принимает решение? | не знаю / согласование | двое | говорю с ЛПР |

**Маршрут:**

| Балл | Статус | Что делаем |
|---|---|---|
| 11–14 | **Горячий** | созвон-диагностика в течение 24 ч, смета в течение 48 ч |
| 7–10 | **Тёплый** | предлагаем Этап 0 (12 000 ₽) или подходящий пакет |
| 4–6 | **Рано** | полезный материал + напоминание через 30–60 дней |
| 0–3 | **Не наш** | вежливый отказ, совет (KIT, Tilda, «останьтесь на МП») |

Стоп-факторы независимо от балла: Q2 = 0 **и** Q1 = 0 (нет ни продаж, ни аудитории) → только Этап 0; хотят аккаунт/домен на нас → отказ.

## 2. Бриф клиента

Форма для клиента — разделы ниже. Колонка «поле» — ключ в JSON калькулятора.

| Вопрос | Поле | Варианты |

## 3. Как считается цена

```
часы_работы = база + ⌈драйвер / шаг⌉ × часы_за_шаг          (нормы — works.mjs)
часы_работы × K_общий × (K_каталог для блока «Каталог»)
K_общий = материалы (1 / 1,15 / 1,3) × срочность (1 / 1,25) × ЛПР (1 / 1,1)
K_каталог = данные (1 / 1,2 / 1,4)
Q04 исправления = 10% от часов ноукода
стоимость = Σ часы × ставка роли
скидка: пакет — 10%; индивидуальная смета — 40+ ч 5%, 80+ 10%, 120+ 15%, 160+ 20%
срок = ⌈часы самой загруженной роли / 20 ч в неделю⌉ + 1 неделя на ожидания (банк, материалы)
```

**Правило выбора формата:**

- Бриф в границах пакета (товаров ≤ лимита, без опций уровня 3) → **пакет по фиксированной цене**.
- Выходит за границы → **смета калькулятора, формат «ФИКС ±30%»**: перерасход до 30% за наш счёт, сверх — доплата; экономия больше 30% — возврат.
- Есть работы уровня 3 без ТЗ (M05, M06, нестандартная 1С) → эти работы — **по часам**, остальное — фикс.

## 4. Проверка сметы перед отправкой (чек-лист PM)

- [ ] Источник товаров и качество данных проверены глазами (открыл файл или 10 карточек на МП).
- [ ] Тариф InSales и нужные приложения проверены на сегодняшнюю дату.
- [ ] FBO/FBS уточнён, если есть маркетплейсы.
- [ ] Для 1С есть контакт 1С-специалиста клиента.
- [ ] В смете отдельной строкой: что платит клиент сторонним сервисам (подписка, тема, эквайринг, касса, МойСклад, доставка).
- [ ] Срок считается от даты получения материалов, а не от оплаты.
