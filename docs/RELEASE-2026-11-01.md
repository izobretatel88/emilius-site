Удаляет из выходной папки только `/os/`, затем проверяет внутренние ссылки, canonical, отсутствие noindex/dev-ссылок, подпись 5/15 и служебные файлы. `deploy:prod` использует ту же команду подготовки.

## Публикация по отдельной команде

Из утверждённого коммита main:

```sh
BEGET_KEY=~/.ssh/codex_beget BEGET_SSH=emilso@emilso.beget.tech BEGET_DIR=emilius.agency/public_html npm run deploy:prod
```

Скрипт переименует `robots.txt` в `robots-main.txt`: `.htaccess` отдаёт открытый robots только основному домену, технические адреса закрывает. Подготовленный архив содержит обычный `robots.txt` и предназначен для проверки; для выкладки использовать скрипт выше. `rsync --delete` удаляет устаревшие файлы, исключая `.well-known/` и `emilius-telegram.php`.

После выкладки: проверить HTTPS и www/http-редиректы, 404, старые адреса Tilda, robots/sitemap/canonical, наличие Метрики, тестовую заявку с доставкой в Telegram, голосовой виджет и мобильное меню/сравнения. При ошибке вернуть снимок предыдущего `public_html`. DNS-откат из старого документа применять только если в рамках публикации действительно менялся DNS и старое назначение заново проверено.
