# Блог: как добавить статью

Раздел `/blog/` собирается из файлов `src/content/blog/<адрес-статьи>.md`. Имя файла — это адрес: `edinye-ostatki-wb-ozon-insales.md` → `/blog/edinye-ostatki-wb-ozon-insales/`.

## Шапка статьи

```yaml
---
title: "До 60 знаков — идёт в <title> и в выдачу"
h1: "Заголовок на странице, может быть длиннее и живее"
description: "140–160 знаков: что узнает читатель"
date: 2026-10-28            # дата публикации
updated: 2026-10-28         # необязательно; если отличается от date, показывается «обновлено»
draft: true                 # true — не попадает в продакшен-сборку
reviewBy: 2026-11-27        # когда перепроверить цены и тарифы
cover: /blog/<адрес>/cover-og.jpg   # 1200×630: превью в списке и в соцсетях
coverAlt: "Что нарисовано на обложке"
readingMinutes: 12
mainQuery: "главный поисковый запрос"
tags: [InSales, Wildberries]
faq:                        # попадает в разметку FAQPage; дублируйте вопросы из текста
  - q: "Вопрос?"
    a: "Короткий ответ."
---
```

Схема проверяется при сборке (`src/content.config.ts`): забытое поле или слишком длинный `title` остановят сборку.

## Картинки

Кладём в `public/blog/<адрес>/`, в тексте пишем путь от корня: `![описание](/blog/<адрес>/схема.webp)`. Размеры WebP плагин подставляет сам, на превью добавляет `BASE_PATH`. Подпись под картинкой — абзац сразу после неё. Описание (alt) обязательно.

Внутренние ссылки тоже пишем от корня (`/services/insales-shop/`). Ссылки на услугу из статьи помечаем `?utm_source=blog&utm_medium=article&utm_campaign=<адрес>`: по `utm_source=blog` срабатывает цель Метрики `blog-to-landing`.

## Что умеет текст

Заголовки `##` попадают в оглавление (от 4 штук), таблицы получают прокрутку на телефоне, блок кода (```) получает кнопку «Скопировать» (цель `blog-copy-prompt`), цитата `>` оформляется как спокойный призыв. Подсветка кода отключена: это промпты и артикулы, а не программы.

## Черновики и превью

- `draft: true` виден в `npm run dev` и в сборке с `PREVIEW=1`, помечается «черновик» и закрыт от индексации.
- Обычная продакшен-сборка (`npm run build`) черновики не выпускает. Если публикуемых статей нет вовсе, нет и `/blog/`, и записи в карте сайта, и ссылки «Блог» в подвале.
- Посмотреть черновик локально: `PREVIEW=1 npm run build && npx astro preview`.
- Картинки из `public/blog/` попадают на сервер при любой выкладке, даже если статья в черновике. Они никуда не ведут, но по прямому адресу открываются. Если картинки секретны, не кладите их в репозиторий до публикации: он публичный.

## Публикация

1. Перепроверить цены и тарифы, поставить `date` и `updated`, убрать `draft`.
2. `npm run build`, посмотреть `dist/blog/…`, карту сайта (`sitemap-0.xml`).
3. PR в `main`, выкладка на Бегет — по прямой просьбе владельца (`npm run deploy:prod`).
4. После выхода: Яндекс Вебмастер — переобход адреса; Метрика — цели `blog-to-landing` и `blog-copy-prompt` (их нужно завести в счётчике один раз).
5. Через 30 дней — обновить цены, поставить новый `updated`.

## Что в разметке

На странице статьи: `og:type=article`, `article:published_time`, своя обложка и alt, три блока JSON-LD (`BlogPosting`, `FAQPage`, `BreadcrumbList`). Издатель и автор — организация «Эмилиус Эдженси».
