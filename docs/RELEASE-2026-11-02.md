### Порядок последующей публикации

1. Получить прямую команду владельца на публикацию и отдельно на перенос в main.
2. Зафиксировать текущий серверный релиз для отката, не выводя и не включая в архив исходников серверные секреты.
3. Выполнить штатный `deploy:prod` с ключом Codex, как описано ниже. Скрипт заново собирает и проверяет release, переименовывает robots.txt в robots-main.txt для Apache.
4. Проверить HTTPS, canonical, robots, карту сайта, 404 и страницу проектов. Сквозную тестовую заявку отправлять только по явному разрешению.
5. При регрессии восстановить предыдущие файлы сайта из серверного снимка с сохранением `/extra/`, SSL и конфигурации формы. Исторический откат DNS на Tilda из старого RELEASE.md не применять.

Автоматическая проверка безопасности отклонила попытку нажатия кнопки заявки как потенциальную отправку во внешний Telegram/сервис; проверка ограничена расчётом и переносом ответов. Сквозной тест выполнить отдельно на Бегете после разрешённой выкладки.
- Состояние HTTPS, серверных редиректов, 404 и доставки robots через Apache проверить после публикации: Astro preview не исполняет `.htaccess` и PHP.
- Lighthouse и полный повторный axe-аудит в этой сессии не запускались. Прежние показатели из документов Claude не считаются новыми замерами объединённого кандидата.
