# Уроки из проектов: память коммуникаций

Источник — выгрузка «Память коммуникаций» из VnimNomic App: 462 сигнала из рабочих чатов, извлечены ИИ, разобраны 06.10.2026. Код сигнала (`HA-002`, `EN-005`…) ведёт к строке выгрузки; соответствие префиксов проектам — в приватной копии. Репозиторий публичный, поэтому здесь нет имён клиентов, сотрудников и цитат.

Метка «(1)» означает, что вывод держится на одном сигнале, «(мнение)» — позиция участника, а не проверенная практика. Часть сигналов — про Tilda, SEO и ботов, сюда взяты только правила, которые переносятся на магазин InSales.

## 1. Правила процесса

**Старт**
- Порядок: утверждённое ТЗ → договор (ТЗ внутри) → предоплата → доступы. Работа стартует после подтверждения оплаты, срок считается от полноценного старта (HA-052, EN-010, SV-012).
- До первого созвона PM присылает 3–4 вопроса и пишет, что для созвона хватит ответов на первые три (HA-001, DY-001).
- Техаудит существующего сайта — до того, как называть объём и сроки (SL-021, SK-002, HA-056).
- От клиента — один представитель, который ставит и принимает задачи (EN-010, SL-011, SL-025).
- В клиентском чате — закреплённый навигационный пост одинакового состава: задачи, ТЗ, структура, тестовый домен, SEO-карта (HA-023, HA-060, MG-001).
- Протокол каждой встречи — в чат клиента. ИИ-черновик помечать «возможны неточности» (HA-005, NE-001).
- В первом сообщении — определения терминов и просьба прислать 3 понравившихся и 3 непонравившихся референса (UD-003, NE-002).

**Сбор требований**
- Сразу спросить про склады и точки отгрузки (HA-067). Проверить, что каталог существует (EN-001). Выгрузку 1С запрашивать с форматом import.xml / offers.xml, конфигурацией и контактом 1С-специалиста (HA-006).
- Ограничения темы InSales проверять до согласования прототипа. Например, меню каталога в мобильной версии (HA-056, HA-061).
- Устные запросы — в бэклог в тот же день (SS-004, BV-002). Неясные — user story с критериями приёмки (SL-012).
- Собрать график отпусков обеих сторон (HA-064). Медленному клиенту — регулярные созвоны с ЛПР (BV-019).

**Доступы**
- Две учётки InSales: клиента и агентства (HA-003). Пароли и коды 2FA в чат не писать (HA-010, HA-016, HA-040). Список нужных прав — заранее (SV-009, SV-010).
- Клиент может заблокировать учётку агентства при превышении тарифа — предупреждать (SS-008, ML-003).
- Работы в боевой 1С — только по письменному плану (HA-019).

**Приёмка**
- Внутренняя: самопроверка → QA по критериям → проверка PM → сверка плана и факта. Внешняя: отчёт план / факт, дефекты за счёт агентства, новые пожелания — через запрос на изменение, обратная связь за 3 рабочих дня (HA-077).
- Два шага: на тестовой теме, затем на боевой (AG-024, MG-009). Подтверждение — текстом в чате, даже после созвона (BV-024, EN-006).
- Тестировать путь до оплаты и передачи в доставку, а не до корзины (DM-007, HA-073). Проверить все формы, включая «в один клик» (MT-004, VB-018, BV-008). Тестовые товары удалить сразу (ZL-017).

**Передача**
- Видеоинструкции по товарам, каталогу и баннерам, демонстрация сайта (EN-008, ZL-008). Как сбросить кэш темы (VB-021). Регламент заполнения карточек, если код завязан на характеристики (BV-010).
- Предупредить о первой оплате платформы и о том, как платить. Один магазин заблокировали за неоплату (EN-014, EN-007).

**Учёт времени и закрытие**
- Факт — только таймером, оценка — в отдельном поле (KT-004). Анализ тоже трекается (BV-001). Время на исправление своей ошибки клиенту не выставляется (BV-009, WZ-012).
- Отклонение факта от плана больше ~15% — исполнитель пишет причины (EN-013).
- Задачи, зависящие от клиента, вычитаются из заказа: сделанное оплачивается, остальное уходит в новый заказ (SK-003, VS-005, EN-005, WZ-009, DM-009). Пожелания не висят в старом заказе (HA-036, HA-080).
- Заказ закрывается письменным итогом с датой (BV-014).

## 2. Красные флаги

| Признак | Что делать | Сигналы |
|---|---|---|
| Клиент тормозит обратную связь | Сдвигать сроки с уведомлением. Пауза от 2 недель — стоп с письменным уведомлением. Спрашивать: «ждём вашего выбора или делаем по-своему?» | BV-005, SL-011, SL-023, VB-020, SK-004 |
| Правки без ТЗ | Пауза и брифинг. Ограниченный бюджет значит ограниченное число вариантов | NE-003, NE-005 |
| Задачи от нескольких человек | Один представитель | SL-025 |
| ТЗ растёт после старта | Новая итерация и новая оценка | ML-008, MG-006, SV-005 |
| Неоплата прошлого заказа | Новые задачи — после оплаты | SL-028, M2-001, NE-006, SS-003, VB-009 |
| «Срочно, на 5 минут», давление | Сначала договорённости. Срочное — по полной ставке | SL-017, SL-033 (мнение) |
| Старая тема InSales, чужой код | Не оценивать без анализа. Предложить переход на тему 4-го поколения | GB-003, GB-004, SK-002 |
| 1С без порядка в данных | 1С-специалист со стороны клиента. Агентство учёт не чинит | HA-007, HA-018, WZ-001 |
| Клиент не знает свою логистику | Логистику формирует клиент, агентство оценивает реализуемость | HA-032, HA-075, HA-028 |
| Неясно, что делает сам клиент | Список «на стороне клиента» в договоре | HA-014, HA-004 |
| Клиент в кризисе | Предоплата | ZL-022 (1) |

## 3. Ошибки и уроки

| Что случилось | Мера |
|---|---|
| Выгрузка 1С пришла бэкапом .dt (HA-006) | Указывать формат, версию, ответственного |
| Обмен 1С молча остановился, фото с тем же именем не обновилось (HA-034) | Проверять дату последнего обмена, учить полному обмену |
| Цена за 1 шт. показалась как за 2 (HA-027) | Проверять цену, единицы и количество в карточке |
| Склады озвучили в день запуска (HA-067) | Вопрос в брифе |
| Не было отдельного тестирования (HA-079) | Строка тестов в смете |
| Предоплата по оценке 45 ч, факт 56–67 ч (HA-050, HA-078) | Коридор ±30% и предупреждение о доплате |
| Индексировалась копия или демо-контент (SL-010, EN-011, HA-066) | Закрыть индексацию до SEO-проверки, чистить демо-контент темы |
| После переезда ~250 URL отдавали 404 (SS-001) | Карта редиректов до переезда |
| ЮKassa не показывала способы оплаты без кассы (ZL-009) | Касса — на этапе диагностики |
| Массовая смена артикулов сбила подборки (ZL-010) | Предупреждать о побочных эффектах пересоздания товаров |
| Старый common.js ломал корзину, скрипты привязаны к классам виджетов (SV-014, VB-015) | Проверять библиотеки темы и сторонние скрипты после правок |
| Работа начата без твёрдого «да» (KT-001, KT-002) | Сначала оценка и согласие. Прототип тоже платный |

## 4. Цена и оплата

- Базовая ставка ноукода — 2 400 ₽/ч (DY-003, MG-002, BV-006). Для давних клиентов бывали 1 500–2 000 ₽/ч (AG-003), для дизайна в оценке — 2 000 ₽/ч (HA-049).
- Ориентиры по магазинам: запуск по шаблону — 25 ч ≈ 60 тыс. ₽ (EN-005); запуск с 1С — оценка ~90 тыс. ₽ за 45 ч, факт 67 ч (HA-049, HA-078); доработка темы — фикс 42 ч ≈ 100 тыс. ₽ (VS-003).
- Опции с ценой: модуль оформления заказа — 16 800 + 12 000 ₽ интеграция (WZ-008, DM-006); подключение ЮKassa и кассы — ~4 ч (ZL-004); аудит критических ошибок — 4 ч ≈ 9 000 ₽ (BV-007); ускорение — фикс ~3,5 ч (VB-013); 152-ФЗ на формах — ~6 ч (DY-004); доставка по километражу — 38–45 тыс. ₽ (ML-012).
- Подходы: коридор ±30% (WZ-006, DM-005, VS-003); скидку давать явно, часы не урезать (WZ-003, WZ-004); мелочи — по факту с постоплатой, пачкой (GB-012, BV-021); нестандартные задачи — 100% при успехе, 50% при неуспехе (GB-008); около 3 ч на спонтанные мелочи в каждом заказе (AG-006, AG-035).
- Подрядчики: мелкое через агентство с наценкой 30–40%, крупное — прямой договор (SV-007, MS-004).

## 5. Границы работ: прописывать «не входит»

Тексты и копирайтинг (HA-012) · наполнение каталога после публикации (ML-014) · юридические документы и реквизиты — заполняет клиент (HA-014) · подписка и оплата платформы (EN-007, HA-017) · логистика и мультисклад (HA-032, HA-075) · офлайн-бонусы и интеграция бонусной системы (HA-021, HA-039) · синхронизация с YClients (HA-048) · настройка и порядок в 1С клиента (HA-007, HA-018) · ожидание поддержки ЮKassa (ZL-004) · API служб доставки сверх готовых модулей (HA-033, ML-012) · стандартные оформление заказа и личный кабинет только перекрашиваются (ML-013) · рефакторинг чужого кода без анализа (GB-003) · сбои платформы и внешних сервисов (VS-007, GB-011).

Дефекты по нашей вине исправляем бесплатно (HA-077, BV-009). Гарантия: клиенты просили 90 дней, по договору 60 — вопрос владельцу (WZ-007).

| Возражение | Ответ | Сигналы |
|---|---|---|

## 7. Технические грабли InSales

- **1С.** Автообмен каждые 900 с; «акции» — только отдельной ценой (HA-020). Товары с разным весом без доработки 1С не объединяются (HA-018). Комментарии и статус из 1С не возвращаются в InSales (HA-035). Лимит тарифа по товарам (HA-017).
- **Доставка.** Catapulto — агрегатор для InSales (HA-002). Мультисклад InSales «сыроват», склады лучше вести в 1С (HA-068, мнение). Расчёт по километражу штатно не поддерживается (ML-012). Флористам доставка нужна внутри заказа, а не в комментарии (EN-009).
- **Оплата.** Эквайринг и касса — разные задачи (ZL-009, ZL-015).
- **Бонусы и скидки.** Промокод InSales отключает внешнюю скидку (AG-025, AG-037). Внешняя скидка теряется при смене доставки (AG-046, AG-060). Скидки больше 50% ломали Mindbox (SV-004).
- **SEO и аналитика.** Сохранять старый счётчик (HA-030). Источник заказа в Метрике перезаписывается, когда сотрудники открывают заказ из админки (MS-002).
- **Тема.** Оформление заказа в 4-м поколении через Liquid не меняется (AG-013); свой модуль окупается, если дизайн отходит от стандарта больше чем на ~40% (WZ-008). Виджеты и контент привязаны к теме — сверять тестовую и боевую (AG-021, AG-053).
- **Скорость.** Вынос JS и CSS из виджетов уменьшил главную с 624 до 296 кБ (AG-042, отчёт разработчика). Не больше 2–3 семейств шрифтов (VS-006).

## 8. Находки для опций и апсейлов

1. Аудит после запуска по чек-листу — опция QA-03 (HA-037, HA-074, BV-007).
2. Свой модуль оформления заказа — опция MOD-04 (WZ-008, AG-005, DM-006).
3. Юридический пакет по персональным данным (VB-011, DY-005).
4. Ускорение сайта за фикс с замером до и после (VB-013, VB-014).
5. Пакет часов техподдержки вместо разрозненных мелочей (AG-006, AG-047, DM-001).
6. Сертификаты, подарки, бонусы — отдельная линия работ (AG-049…AG-059).
7. Клиенты, ушедшие с Яндекс KIT из-за проблем с 1С, — аргумент в сравнении платформ (HA-053, HA-054, мнение).
