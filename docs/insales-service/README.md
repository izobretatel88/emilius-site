# Услуга «Интернет-магазин на шаблоне InSales»

Рабочая система: от поиска клиента до сдачи магазина. **Начать с `14-start.md`** — 10 рабочих дней владельца до первой оплаченной диагностики и вопросы, ответы на которые ждёт агент. Версия 22 от 07.10.2026: старт продаж и правило для следующих запусков агента — без новых документов до первых фактов. Версия 21 от 06.10.2026: разбор листа лидов одной командой — кому писать сегодня, воронка по каналам, конверсии против порогов, стоимость заявки и проекта против пределов экономики; словарь статусов. Версия 17 от 06.10.2026: цели Метрики на лендинге (счётчик — переменной `YM_ID` при сборке) и источник (UTM) в каждой заявке; UTM-ссылки для каналов. ## Как пользоваться

1. **Пришёл лид** → если с лендинга, в заявке уже ответы и ориентир: `insales-calc.mjs --answers '{…}'` → квалификация из 5 вопросов (`04-estimation.md`) → диагностика.
1а. **Каждый понедельник** → `insales-funnel.mjs лиды.csv`: касания на сегодня, воронка, стоп-правила каналов.
2. **Горячий запрос** (биржа, каталог партнёров, чат) → ответ за 30 минут по `templates/hot-replies.md`.
3. **На диагностике** → файл товаров клиента через `insales-import-check.mjs` → бриф → `calculator.html` или `insales-calc.mjs` → заключение (`templates/diagnostic-report.md`) и КП из `insales-kp.mjs` → после согласования опций — Заказ (`--order`).
4. **Проект** → этапы `05-process.md`, задачи в Weeek из `insales-kp.mjs --tasks` (id каталога + план часов), тесты и запуск — `templates/qa-protocol.md`.
5. **После проекта** → исполнители заполняют `факт_ч` → `insales-calibrate.mjs` даёт строку журнала (`11-improvement.md`) и нормы к правке.
6. **Через 30 дней** → отчёт и абонемент (`12-retention.md`).

```bash
npm run insales:check                      # после любой правки: id работ, цены «от», тарифы, свежесть calculator.html
node scripts/insales-calc.mjs              # 5 типовых сценариев (проверка норм)
node scripts/insales-calc.mjs -v           # с разбивкой по работам
node scripts/insales-calc.mjs brief.json   # смета по брифу (поля — DEFAULT_BRIEF в calc/estimate.js)
node scripts/insales-calc.mjs --html       # пересобрать calculator.html после правки CSV
node scripts/insales-kp.mjs brief.json > КП.md            # КП: пакет, опции с ценами, не входит, бюджет первого года
node scripts/insales-kp.mjs brief.json --order > Заказ.md # Заказ к договору: работы по id, оплата, приёмка, гарантия
node scripts/insales-kp.mjs brief.json --tasks > задачи.csv # задачи для Weeek: id, этап, роль, план часов, пустой факт
node scripts/insales-calibrate.mjs п1.csv п2.csv п3.csv  # после проектов: строки журнала калибровки и нормы к правке
node scripts/insales-unit.mjs --plan 500000 --letters 20 # агентству: маржа, предел за контакт, воронка и сборщики на план
node scripts/insales-funnel.mjs лиды.csv --spend директ=15000 # понедельник: кому писать, воронка, цена заявки и проекта по каналу
node scripts/insales-margin.mjs --check 3500 --cost 1400 # селлеру: маржа площадка vs сайт, окупаемость
node scripts/insales-import-check.mjs товары.csv --brief brief.json   # проверка файла клиента + поля брифа
node scripts/insales-site-check.mjs бренды.txt > лиды.csv          # проспектинг: сегмент, признак, повод
python3 scripts/import-vnimnomic.py "<Задачи и подсчеты>.xlsx"   # обновить data/orders-hours.csv из новой выгрузки
```

Сырые выгрузки с перепиской клиентов и деньгами в публичный репозиторий не кладём. Соответствие кодов проектам пишется в `data/private/` (в `.gitignore`).

## Главные решения v1

- Сдаём по рабочему заказу с телефона, а не по «сайт готов».
- Три пакета: Старт от 75 тыс. ₽, Магазин от 95 тыс. ₽, Селлер от 100 тыс. ₽ (v5: «от» — минимум калькулятора, ниже смета не опускается) — в коридоре студий 80–115 тыс. ₽. Платформа отдельной строкой: 2 700 ₽/мес, селлеру «Комбо» 6 600 ₽/мес.
- Позиционирование для селлеров: «добавить канал», а не «уйти с маркетплейсов».
- Обязательный вопрос о трафике в квалификации: магазин без источника покупателей не продаём молча.
- Все доступы на клиенте.
