# 3. Конструктор услуги: как собрать проект из работ

Каталог работ — `tool/works.mjs` (источник), `data/works.csv` (для таблиц). У каждой работы: код, модуль, этап → задача → подзадача, описание, когда нужна, входные данные, результат, часы мин/норматив/макс, единица, сложность 1–3, роль, зависимости, риски, варианты исполнения, цена за единицу.

Здесь — правила выбора по направлениям: какие развилки бывают, какой вариант выбирать и где проекты ломаются.

## Как собирается проект

```
бриф (04-estimation.md)
  → scope(): какие работы и сколько единиц   (tool/rules.mjs)
  → часы = норматив × количество
  → + управление 12% (мин. 3 ч) + резерв 5/10/20% по сложности
  → смета
  → если бриф в границах пакета: пакет + допработы сверх состава пакета
  → КП
```

Порядок выполнения задают зависимости (`deps`). Критический путь типового проекта: B01 → B04 → K01 → K03 → импорт (K06/K07) → B12/B13 → B18 → B19 → B21. Эквайринг (B12) подаётся в **первую неделю**: проверка сайта эквайером идёт 3–10 дней и чаще всего сдвигает запуск.

## Каталог

| Развилка | Варианты | Правило |
|---|---|---|
| Сколько товаров | до 50 / 50–500 / 500–2 000 / > 2 000 | До 30 — можно вручную (K04). Больше — только импорт (K06/K07) или учёт. > 2 000 — сложность 3, смета |
| Источник | таблица / WB-Ozon / МойСклад / 1С / старый сайт / вручную | Главный источник правды — учёт, если он есть. Иначе — площадка. Ручной ввод — последний вариант |
| Категории | до 20 / 20–60 / > 60 | Структура по тому, как ищет покупатель («Для кошек → Корм → Сухой»), а не как на складе. Больше 3 уровней не делаем |
| Варианты | нет / у части / у всех | Варианты — это остатки по размеру/цвету. Если они есть в учёте, тянем из учёта, вручную не дублируем |
| Фильтры | 3–7 главных свойств | Значения чистим до импорта: «синий», «Синий», «синий » — один цвет |
| Фото | готовы / разные форматы / нет | Нет фото — не начинаем каталог. Съёмку не делаем. Разный формат — K09 |
| Описания | есть / с МП / нет | С МП — оставляем, правка — опция. Нет — K10 (нейросеть + редактура, факты подтверждает клиент) |

**Где ломается:** клиент присылает товары частями (сдвиг сроков) → правило: каталог принимаем одним файлом по нашему шаблону, дедлайн — день 3 проекта. Артикулы на сайте и МП разные → синхронизация невозможна без сопоставления (MP2).

## Импорт

1. Шаблон таблицы из заготовки → клиенту в день 1.
2. Пробная загрузка 10 товаров, проверка карточки на телефоне.
3. Полная загрузка, чистка (K08 — на каждые 100 товаров).

С WB/Ozon (K07): тексты площадки заточены под её поиск (повторы ключей) — на сайте выглядят спамно. Предлагаем правку 10–20 главных карточек как опцию (K10).

## Дизайн и изменение шаблона

| Уровень | Что это | Работа | Риск |
|---|---|---|---|
| 0. Настройки темы | Цвета, шрифты, логотип, блоки главной | B04, B06 (в базе) | Нет |
| 1. Графика | Баннеры, иконки, плашки | D01, D02 | Нет |
| 2. Страницы из блоков | Лендинг акции, «Оптовикам» | D03 | Нет |
| 3. Мелкая правка кода | Вывести поле, скрыть элемент | D04 (за правку) | Может слететь при обновлении темы — пишем в паспорт |
| 4. Нестандартный блок | Калькулятор, конструктор набора | D05 + D06 | Сложность 3. > 2 блоков — это уже не шаблонный продукт |

**Правило выбора темы:** сначала каталог и сценарий покупки (много вариантов → тема с хорошим выбором размера; большой каталог → сильные фильтры; 20 товаров → акцент на карточку и бренд), потом картинка. Показываем 2–3 демо с товарами клиента.

## Оплата

- Один способ входит в базу, второй — +0,5 работы B12.
- Варианты: встроенные платежи InSales, ЮKassa, Т-Банк, CloudPayments; СБП — через провайдера.
- Чеки 54-ФЗ: касса провайдера или своя онлайн-касса. Без кассы не запускаем онлайн-оплату.
- Тест: реальный платёж минимальной суммы и возврат.

## Доставка

- В базе: самовывоз/курьер по зонам + 1 служба с расчётом (СДЭК, Почта, Boxberry, агрегатор). Каждая следующая — +0,5 B13.
- Без веса и габаритов у товаров расчёт неверный. Собираем в таблице импорта (колонки обязательны).
- Агрегатор (ApiShip и аналоги) — когда нужно 3+ службы.

## Учёт: МойСклад и 1С

| | МойСклад | 1С |
|---|---|---|
| Сложность | 2 | 3 |
| В пакете | «Магазин + синхронизация» | Только смета |
| Часы (норматив) | ~9 ч | ~20 ч + координация программиста 1С |
| Главное условие | Чистый справочник с артикулами, платная опция онлайн-торговли МС | Типовая конфигурация (УТ/УНФ/Розница/КА), доступный программист 1С клиента |
| Порядок | MS1 обследование → MS2 подключение → MS3 сопоставление → MS4 остатки → MS5 цены → MS6 заказы → MS7 тест → MS8 инструкция | C101 конфигурация → C102 способ обмена → C103 узел в 1С → C104 товары → C105 характеристики → C106 остатки → C107 цены → C108 заказы → C109 контрагенты → C110 тест → C111 ошибки → C112 регламент |
| Где ломается | Дубли и товары без артикула | Нет программиста 1С; нетиповая или сильно переписанная 1С (отдельная оценка) |

**Правило:** если учёт есть — он главный, сайт и площадки берут из него остатки и цены. Если у селлера нет учёта и 2+ площадки, рекомендуем МойСклад как центр (InSales ↔ МС ↔ WB/Ozon) — это чаще дешевле, чем потом разбираться с двойными продажами.

## Маркетплейсы

- За каждую площадку: MP1 подключение, MP2 сопоставление (на 100 товаров), MP3 остатки, цены, тест.
- Режимы: только остатки / остатки + цены / + заказы. Начинаем с остатков.
- Страховой буфер остатков (1–2 шт.) против двойной продажи последней единицы — штрафы площадок дороже упущенной продажи.
- Через InSales напрямую или через МойСклад — решается на Этапе 0 (Z04) по тарифу и наличию учёта.
- **Проверить перед КП:** на каком тарифе InSales доступна синхронизация с МП (в источниках 2026 года — тариф «Комбо»/«Мульти»; insales.ru не открывался).

## CRM и телефония

- Нужна, если заказы обрабатывают 2+ менеджера или продают по телефону. Иначе хватает заказов InSales.
- CR1 (2–5 ч) — amoCRM / Битрикс24 / RetailCRM. RetailCRM — лучший выбор для чистой розницы; amo/Битрикс — если CRM уже есть.

## SEO

- Базовое (B16) — у всех: шаблоны мета, robots, sitemap, ЧПУ, без дублей.
- Семантика (S1, 6–16 ч) — когда SEO — один из каналов первых заказов (локальный магазин, нишевые запросы). Пример: Happy Animal, локальные запросы «зоомагазин Гольяново».
- Тексты категорий (S2) — по количеству категорий из семантики.
- Переезд (R1–R6) — обязателен, если у старого сайта есть трафик из поиска: без 301-редиректов позиции теряются.

## Аналитика

- База (B15): счётчик Метрики на аккаунте клиента, вебвизор, цели «корзина → оформление → заказ», Вебмастер.
- E-commerce (AN1): обязательно, если будет реклама — иначе не видно выручки по источникам.
- Отчёт 30 дней (AN2) — продаём всем как мост к поддержке и маркетингу.

## Контент

Чья работа — фиксируем в брифе. По умолчанию тексты условий доставки/возврата и фото — клиента; наши — шаблоны страниц, мета, структура. Если контента нет — K09/K10/D02 по прайсу, а не «как-нибудь в процессе».
