# 03. Бриф, квалификация и оценка проекта

Цель: цена проекта получается из ответов клиента почти без участия человека. Цепочка:

```
Квалификация (5 вопросов, в переписке) ──► балл лида ──► бриф (20 вопросов, форма) ──► калькулятор ──► КП
                                                                                         └──► Этап 0 уточняет и фиксирует
```

## 1. Квалификация лида (до созвона, 5 вопросов)

Задаём в переписке, по одному-два за раз. Ответы → балл 0–10.

| # | Вопрос | Ответ → баллы |
|---|---|---|
| Q1 | Где сейчас продаёте и сколько примерно заказов в месяц? | Нет продаж — 0 · соцсети/офлайн до 50 — 1 · МП или офлайн 50–500 — 2 · 500+ — 3 |
| Q2 | Это ваш бренд/производство или перепродажа? | Перепродажа без бренда — 0 · свой бренд/СТМ/производство — 2 |
| Q3 | Откуда придут первые покупатели на сайт? | «Не знаю» — 0 · соцсети/база/офлайн-клиенты/бренд-поиск — 2 · + готов бюджет на рекламу — 3 |
| Q4 | Кто будет обрабатывать заказы с сайта? | Никто/я, когда успею — 0 · конкретный человек — 1 |
| Q5 | Какой бюджет на запуск закладываете? | До 60 тыс. — 0 · 60–150 тыс. — 1 · 150+ тыс. — 1 (и маркер «Бизнес») |

**Решение:**
- **7–10** — горячий. Сразу созвон-диагностика (бесплатно 30 мин) → КП по калькулятору → Этап 0 включён в проект.
- **4–6** — тёплый. Предлагаем **Этап 0 платно**: снимет неопределённость с источником клиентов.
- **0–3** — не наш сейчас. Даём полезный материал (смета владения, чек-лист «готов ли я к магазину»), ставим напоминание через 3 месяца.
- **Стоп-флаги** (любой = не берём в пакет): нужен «как у Ламоды» за 90 тыс.; клиент хочет аккаунт и домен на агентстве; не готов к предоплате; требует гарантию выручки.

## 2. Бриф клиента (форма, 15 минут)

Вопросы сгруппированы так, чтобы каждый ответ превращался в поле калькулятора (в скобках). Форму можно сделать в Google Forms/Яндекс Формах один к одному.

**О бизнесе**
1. Название, сайт (если есть), ссылки на WB/Ozon/соцсети.
2. Чем торгуете и кто покупает? Есть ли повторные покупки? (`crmk`)
3. Есть ли офлайн-точка? Адрес. (`geo`)
4. Кто будет вести заказы и товары на сайте? (`kc`, `staff`)

**Товары**
5. Сколько товаров (артикулов) запускаем на сайте сначала? (`sku`)
6. Где сейчас лежат данные о товарах: таблица / WB-Ozon / старый сайт / нигде? (`src`)
7. У товаров есть варианты (размер, цвет, объём)? (`variants`)
8. По каким характеристикам покупатель выбирает (фильтры)? Перечислите. (`props`)
9. Фото: есть отдельные для сайта / только с инфографикой с МП / нет? (`photos`)
10. Описания: есть / только с МП / нужно писать? (`texts`)

**Каналы и учёт**
11. На каких площадках продаёте и нужны ли общие остатки с сайтом? (`mps`)
12. Где ведёте учёт: таблицы, МойСклад, 1С (какая)? Нужны ли заказы с сайта в учёте? (`acc`)
13. Есть ли CRM, телефония? (`crm`, `tel`)

**Оплата и доставка**
14. Нужна онлайн-оплата? Есть договор с банком/ЮKassa? Онлайн-касса? (`pay`, `kassa`, `pay3`)
15. Как доставляете: курьер, самовывоз, СДЭК, Почта, Яндекс? (`dlv`)

**Внешний вид и контент**
16. Есть логотип, цвета? Пришлите 2–3 сайта, которые нравятся.
17. Какие страницы нужны кроме стандартных (опт, о бренде, таблица размеров)? Тексты есть? (`pages`, `ptexts`)
18. Нужно ли что-то, чего нет в шаблоне? Опишите словами. (`x1`, `x2`, `x3` — оценивает разработчик)

**Переезд и маркетинг**
19. Есть ли старый сайт, который приносит посетителей из поиска? (`urls`, `mgp`)
20. Как планируете приводить покупателей: соцсети, реклама, SEO, база? Бюджет в месяц? (`ads`, `sem`)

**Сроки и бюджет**
21. К какой дате нужен запуск и почему именно к ней? (`ku`)
22. Какой бюджет на запуск и на первые 3 месяца после?

## 3. Система сложности

Класс проекта задаёт пакет, срок и кто ведёт.

| Класс | Признаки | Пакет | Ведёт |
|---|---|---|---|
| **S** | ≤100 SKU, нет учёта и МП, шаблон как есть | Старт | PM + настройщик |
| **M** | ≤1000 SKU, 1–2 МП или МойСклад, переезд с Tilda | Селлер | PM + настройщик + разработчик на интеграции |
| **L** | >1000 SKU, 1С, CRM, переезд с поиском, правки кода | Бизнес + модули | PM + разработчик весь проект |
| **XL** | Кастомный дизайн, B2B-цены, нестандартная 1С, >10 000 SKU | Не пакет | Отдельная оценка после Этапа 0 |

## 4. Расчёт (то, что делает калькулятор)

```
Часы работы  = база + за_единицу × количество        (по каждой работе из каталога)
Каталог (M3) × коэффициент качества данных           1,0 чистые · 1,2 средние · 1,5 плохие
Стоимость    = Σ часы × ставка роли
Управление   = 10% часов × ставка PM
Итог         = (стоимость + управление) × готовность клиента × срочность × 1,10 (запас)
Цена         = округление вверх до 5 000 ₽
Срок, недель = ⌈часы / 15⌉ + 1   (15 продуктивных часов проекта в неделю + неделя на ожидание клиента)
```

| Коэффициент | Значения | Когда |
|---|---|---|
| Качество данных | 1,0 / 1,2 / 1,5 | Дубли, нет артикулов, разные единицы, нет фото |
| Готовность клиента | 1,0 / 1,1 / 1,25 | Нет ответственного, материалы «потом пришлём» |
| Срочность | 1,0 / 1,25 | Срок короче расчётного в 1,5 раза |
| Запас на риски | 1,10 | Всегда |

**Автоматические предупреждения:** цена < 60 000 ₽ → не «под ключ»; кода и учёта > 12 ч → эти модули по факту с потолком +20%; 1С → программист 1С клиента и платная интеграция InSales.

## 5. Что фиксируем после Этапа 0

КП (одна страница): состав (список работ из калькулятора), что не входит, цена, срок по неделям, график оплат, смета владения, список материалов от клиента с датами. Подписывается как Заказ к рамочному договору.

## 6. Как улучшать нормативы

После каждого проекта: план-часы из калькулятора vs факт-часы из Weeek по каждой работе. Отклонение >25% на трёх проектах подряд — правим `tools/works.py` и пересобираем. Ведём в таблице «Нормативы: план/факт» (см. `12-improvement.md`).
