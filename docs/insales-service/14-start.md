Всё, что осталось в бэклоге (`11-improvement.md`), упирается во владельца: кабинет партнёра InSales, юрист, выплаты исполнителям, отправка писем от своего имени. Сайты InSales, WB, Ozon, vc.ru и бирж из среды агента закрыты, проверить их он не может.

Этот файл — короткий путь до первой оплаченной диагностики: что сделать, сколько это займёт, что сообщить агенту. Новых документов до первых ответов владельца агент не пишет (§4).

## 1. Какая ветка актуальна

Каждый запуск агента создавал свою ветку `claude/upbeat-volta-*`. Актуальная — та, где лежит этот файл: в ней итерации 1–22 одной линией. Остальные ветки `upbeat-volta-*` — промежуточные копии, их можно удалить. Ветки `pa3hpb`, `p20h3n`, `oa04nr` — параллельные черновики в других папках (`docs/insales-shop/`, `sales/insales-shop/`); полезное из них уже перенесено (пакет «Экспресс» — бэклог 9а).

Чтобы лендинг появился на `/dev/`, актуальную ветку нужно влить в `dev` — по слову владельца.

Первая продажа требует четырёх вещей: заявки, диагностики, КП и Заказа к договору. Всё остальное (видео, найм, калибровка, экономика) — после.

**Дни 1–2:** шаги 1–5 (~2 ч). **Дни 3–10:** шаг 6 каждый день, касания 2 и 3 по шести письмам — на 3-й и 8-й день (скрипт напомнит), понедельник — шаг 7. Итого за 10 дней ~6 ч владельца.

Если к 10-му дню ни одной диагностики — не писать новые тексты, а смотреть, на каком шаге воронки стоит: нет ответов — повод письма (`09-outreach.md`), ответы есть, диагностик нет — переход к платной диагностике (`10-sales.md`, решение 4 в `04-estimation.md` §5).

## 3. Что сообщить агенту

Агент запускается по расписанию и читает этот раздел. Владелец вписывает ответ в колонку «Ответ» (или пишет в сессию одной строкой «тарифы: 2 700 / 6 600, карточки WB без Комбо — нет»). Следующий запуск переносит ответ в расчёты и вычёркивает строку.

| # | Вопрос | Ответ | Куда пойдёт | Что изменится |
|---|---|---|---|---|
| 1 | Цена тарифа «Интернет-магазин» и «Комбо» помесячно, ₽ | | `calc/estimate.js` (`base`), `insales-lint.mjs` | бюджет первого года в КП |
| 2 | Можно ли загрузить карточки с WB/Ozon без «Комбо»? да / нет | | `pickPackage` в `calc/estimate.js` | разовый импорт с площадки без синхронизации станет «Магазином», а не «Селлером»; тариф клиента — «Интернет-магазин», а не «Комбо» |
| 3 | Сколько платим сборщику и контент-менеджеру за час, ₽ (или доля от ставки) | | `insales-unit.mjs --pay` | маржа сценариев и предел стоимости заявки; при доле 60%+ пересмотр цен (`13-economics.md`) |
| 4 | Юрист: Заказ согласован? правки | | `templates/order-example-seller.md`, `insales-kp.mjs --order` | Заказ можно подписывать |
| 5 | Карточка партнёра обновлена? дата | | `08-lead-gen.md` §6, неделя 1 | старт 8-недельного теста, дата начала для `--since` |
| 6 | Можно ли вливать актуальную ветку в `dev`? | | ветка `dev` | лендинг на `/dev/` для просмотра |
| 7 | Happy Animal и Endorphine: согласны на кейс с цифрами? | | `07-landing.md`, блок «Примеры» | кейсы на лендинге |

Ответы на 1, 2 и 3 агент проверяет `npm run insales:check` и отчитывается, сдвинулись ли цены пакетов.

## 4. Правило для следующих запусков агента

Система избыточна относительно числа продаж (ноль). Пока в §3 нет ни одного ответа и в листе лидов нет реальных строк, запуск агента:

1. проверяет `npm run insales:check`;
2. переносит ответы владельца из §3, если появились;
3. если пришёл лист лидов или факт часов — запускает `insales-funnel.mjs` или `insales-calibrate.mjs` и записывает итог в `11-improvement.md`;
4. иначе — не создаёт новых документов и не уведомляет владельца повторно о том же.

Новые материалы появляются, только когда их требует факт: ответ клиента, которого не покрывают шаблоны; отклонение часов больше 20%; канал, сработавший хуже порога.
