# 03. Система оценки проекта

Цель: цена определяется алгоритмом, а не ощущением менеджера. Клиент отвечает на бриф (`04-brief.md`) → ответы записываются в JSON → калькулятор собирает работы из каталога → часы → цена → срок.

```
Бриф (25 вопросов)
   ↓ нормализация: значения по умолчанию + производные количества
Количества (товары, категории, площадки, пары «оплата × доставка», URL…)
   ↓ правила включения работ (поле on в catalog.mjs)
Список атомарных работ (из 117)
   ↓ часы = база + на единицу × количество
   ↓ × коэффициенты риска × стандартизация пакета
   ↓ × ставка тарифа (2 400 / 3 500 / 4 200 ₽)
   ↓ − скидка за объём (40 ч −5%, 80 ч −10%, 120 ч −15%, 160 ч −20%)
Смета: типовая цена, коридор, предоплата 50%, срок, ближайший пакет
```

## Файлы

| Файл | Что это |
|---|---|
| `calculator/catalog.mjs` | Каталог работ: этап → задача → подзадача, часы, сложность, роль, зависимости, риски, правило включения |
| `calculator/calc.mjs` | Калькулятор и правила цены (`PRICING`) |
| `works-catalog.csv` | Тот же каталог таблицей — для Google Sheets и обсуждения с командой (`node calculator/calc.mjs --csv > works-catalog.csv`) |
| `calculator/packages/*.json` | Брифы «на границе пакета» — из них получены цены пакетов |
| `calculator/briefs/*.json` | Примеры и калибровочные брифы |
| `calculator/estimates/*.md` | Готовые сметы по всем брифам |

## Как посчитать проект

```bash
cp docs/insales-service/calculator/briefs/seller.json /tmp/client.json   # правим под клиента
node docs/insales-service/calculator/calc.mjs /tmp/client.json          # смета в markdown
node docs/insales-service/calculator/calc.mjs /tmp/client.json --json   # для CRM/таблиц
```

## Правила

1. **Часы** — чистое время исполнителя. Ставка команды уже включает менеджера проекта и тестировщика (как в прайсе агентства), поэтому отдельных часов «на управление» в смете нет.
2. **Тариф работы**: `nc` 2 400 ₽/ч — ноукод и дизайн на InSales; `dev` 3 500 ₽/ч — код, 1С, МойСклад, CRM; `pm` 4 200 ₽/ч — продакт (этап 0, разбор 30 дней).
3. **Этап 0** продаётся фиксом за 15 000 ₽ (себестоимость по часам ~23 000 ₽ — сознательно ниже, это вход в воронку) и засчитывается в проект.
4. **Резерв на исправления** — 8% от часов настройки (работа S15.03).
5. **Коридор** — разброс по сложности: простые работы −15%/+20%, средние −20%/+35%, сложные −25%/+60%. Клиенту называем типовую цену и верхнюю границу коридора как «не больше, если не меняем объём».
6. **Правило ФИКС** (из процесса агентства): перерасход больше 30% от типовой — доплата по согласованию; экономия больше 30% — возврат разницы.
7. **Срок** = часы / 20 ч в неделю + 1 неделя на ожидание материалов и модерацию платёжного сервиса + 1 неделя на 1С + 1 неделя на переезд.

## Коэффициенты

| Условие | Коэффициент | Почему |
|---|---|---|
| Срочно: срок меньше расчётного | ×1,25 | Параллельная работа, переключения |
| Решение принимают 2+ человека | ×1,05 за каждого сверх первого (до ×1,15) | Согласования |
| Материалов нет, собираем вместе | ×1,10 | Ожидание и переделки |
| Первый сайт у клиента | ×1,05 | Больше объяснений |
| Работа входит в выбранный пакет | ×0,85 | Заготовки: юр. страницы, письма, цели Метрики, чек-лист. **Гипотеза** — проверить по таймеру |

## Система сложности проекта

| Уровень | Признаки | Как продаём |
|---|---|---|
| 1. Типовой | В границах пакета | Фикс-цена пакета |
| 2. Пакет + опции | Пакет + 1–4 модуля из списка опций | Фикс пакета + опции по калькулятору |
| 3. Нетиповой | 1С с доработками, RetailCRM, переезд 1 000+ URL, свой дизайн | Смета калькулятором, этап 0 обязателен, оплата ПРЕД50 + доплата по факту |
| 4. Не наш формат | Кастомная тема с нуля, маркетплейс-агрегатор, сложные B2B-прайсы | Отдельное ТЗ, не эта услуга |

## Калибровка (07.10.2026)

| Проект | Факт / бюджет | Калькулятор | Расхождение и вывод |
|---|---|---|---|
| Endorphine, MVP на шаблоне Moon, 20 товаров вручную | 25 ч (план 20 ч), 59 920 ₽ | 31 ч / 75 000 ₽ | +24%. В калькуляторе есть Метрика, базовое SEO, уведомления в Telegram — в MVP их не было. Допустимо |
| Happy Animal, ~2 000 SKU, 1С, 2 точки | Бюджет этапа «запуск» 80–120 тыс. ₽ (без SEO-проектирования) | 82 ч / 193 000 ₽ | Бюджет клиента был занижен для 1С + 2 000 SKU: одна интеграция 1С ≈ 14–17 ч / 49–58 тыс. ₽. Вывод: при 1С этап 0 обязателен, иначе клиент приходит с ожиданием в 2 раза ниже |
| Рынок, магазин на шаблоне у студий | 75–130 тыс. ₽ | «Старт» 99 тыс., «Маркетплейс + сайт» 159 тыс. | «Старт» в середине рынка; пакет для селлеров дороже студий, но включает синхронизацию с 2 площадками, которую студии продают отдельно |

Первая версия норм дала 56 ч на Endorphine (в 2,2 раза больше факта): нормы ноукод-работ были завышены в ~1,5 раза, обработка фото включалась автоматически, а при учёте в 1С каталог ошибочно считался ещё и через импорт Excel. Исправлено во второй итерации.

## Как улучшать нормы

После каждого проекта: выгрузить таймер Weeek по ID работ (ID ставить в название задачи: `S9.04 Общие остатки`), сравнить с `hTyp` из сметы, поправить `h`/`per` в каталоге, если расхождение по работе больше 30% на двух проектах подряд. Записать в журнал в `11-improvement.md`.
