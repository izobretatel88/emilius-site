# 3. Конструктор услуги: каталог типовых работ

Источник правды — [`data/works.csv`](data/works.csv) (разделитель `;`, открывается в Google Таблицах). Здесь — как им пользоваться и разбор блоков, где чаще всего ошибаются в оценке.

## Структура строки

| Поле | Смысл |
|---|---|
| `code` | Код работы. Буква — блок: A старт, B платформа и тема, C каталог, D страницы, E оплата, F доставка, G заказы и CRM, H учёт, M маркетплейсы, S SEO и перенос, N аналитика, K маркетинг, X модификация темы, T тест, P передача |
| `unit` | Единица: `проект` (разово), `100 SKU`, `SKU`, `категория`, `площадка`, `страница` и т. п. |
| `h_fix`, `h_unit` | Норматив: часы = h_fix + h_unit × количество |
| `role` | Кто делает: R разработчик, N настройщик, D дизайнер, A аналитик/SEO, Q тестировщик, K контент, M основатель |
| `level` | Сложность 1–3: 1 — по чек-листу может джун, 2 — нужен опыт inSales, 3 — разработчик с проверкой основателя |
| `package` | `base` — в «Старте», `cond` — подключается правилом брифа, `opt` — опция, `stage0` — этап 0 |
| `requires` | Зависимости (что должно быть сделано до). `A|B` — любое из |
| `when` / `input` / `result` / `risks` | Когда нужна, что получить от клиента, что на выходе, что может пойти не так |

Иерархия «этап → задача → подзадача → вариант → время → зависимость → стоимость» уложена так: блок (буква) → работа (код) → подзадачи описаны ниже для сложных блоков → вариант выбирается правилом брифа (например, C04 или C05 или C07) → норматив → `requires` → цена = часы × ставка роли.

## Порядок работ (критический путь)

```
этап 0: A01 → A02
старт:  A03 → A04 → B01 → B02
                   ↘ E01 (модерация эквайринга 3–10 дней — запускаем в первый день!)
тема:   B03 → B04 → B05, B06, B07
каталог: C01 → C02 → C03 → C04|C05|C07 → C06 → C11 → C10
учёт/МП: H01|H03… и M01 → M02 → M03 (только после того, как каталог стабилен)
заказы: E01, E02, F01, F02, G01, G02
тест:   T01 → T02 → T03 → T04
сдача:  P01 → P02 → P03 → P04 (14 дней)
```

Параллельно идут три дорожки: **тема** (дизайнер), **каталог** (настройщик/контент), **деньги и доставка** (настройщик, ждём договоры клиента). Узкое место почти всегда — договоры эквайринга и доставки на стороне клиента.

## Каталог (C) — главный источник перерасхода

### Как оценивать объём

| Вопрос брифа | Влияние |
|---|---|
| Сколько SKU (считая варианты как один товар)? | Количество для C04/C05/C11 (в сотнях) |
| Есть варианты (размер/цвет/объём)? | +C03; для одежды — обязательно |
| Откуда товары: таблица, WB/Ozon, старый сайт, учёт, «из головы»? | Выбор C04 / C05 / S05 / H04 / C07 |
| Таблица чистая? (одна строка = один товар, артикулы уникальны, категории заполнены) | Если нет — C06 на каждые 100 SKU |
| Фото: есть ли, одного ли формата | C08, если разного |
| Описания есть? | C09, если нет и источник не МП |
| Вес и габариты есть? | F04, если нет — без них не работает расчёт доставки |
| Сколько категорий и уровней вложенности? | Количество для C01. Больше 2 уровней — переспросить, нужно ли |
| По каким свойствам фильтруют? | Количество для C02 |

### Варианты исполнения импорта

| Вариант | Когда | Плюсы | Минусы |
|---|---|---|---|
| **C05 импорт с WB/Ozon** | Селлер A2 | Фото, описания, характеристики уже есть | Характеристики площадки ≠ удобные фильтры сайта; описания написаны под МП (переспам) — предупредить |
| **C04 из таблицы** | Есть Excel/Google | Быстро, предсказуемо | Таблица почти всегда грязная — смотреть до сметы |
| **H04 из 1С / H01 из МойСклад** | Учёт ведётся | Единый источник правды | Фото и описания в учёте часто пустые → всё равно нужен C04 или C09 |
| **S05 со старого сайта** | Переезд | Сохраняем URL и контент | Нестандартные CMS — оценка после доступа |
| **C07 вручную** | До ~30 SKU, ничего нет | Не зависим от качества данных | 0,2 ч/SKU, дорого на объёме |

### Типовые проблемы

- **Разные артикулы** на МП, в учёте и в таблице → до интеграций согласовать, какой артикул главный. Без этого M01 и H01 сопоставляют товары руками.
- **Варианты как отдельные товары** («Футболка красная S», «Футболка красная M») — склеить до импорта, иначе каталог в 5 раз длиннее и фильтры не работают.
- **Категории МП** («Постельное бельё → Комплекты → Евро») не подходят для навигации сайта. Строим дерево заново в C01.

## Дизайн и шаблон (B, X)

**Граница продукта:** шаблон настраивается штатными настройками темы (B04, B05) плюс до 2–4 мелких правок (X01). Если клиенту нужен свой макет главной (B08) и 2+ новых блока (X02), это класс M/L. Если нужен конструктор в карточке (X03), это не шаблонный продукт: оцениваем как разработку на час команды.

| Подзадача | Норматив | Как сократить |
|---|---|---|
| Выбор темы | 1 ч | Держать шорт-лист 5 проверенных тем по нишам: одежда, косметика, дом и текстиль, еда, техника — **задача на стандартизацию** |
| Стиль: лого, цвета, шрифты | 2 ч | Пресет настроек по каждой теме из шорт-листа |
| Главная из блоков | 3 ч | Типовая структура: обложка → категории → хиты → преимущества → отзывы → о бренде → подписка |
| Правка темы | 2 ч на правку | Все правки — в копии темы и в паспорте, иначе обновление темы их откатит |

## Оплата и касса (E)

Подзадачи E01: выбрать провайдера (ЮKassa, Т-Банк, CloudPayments, Робокасса, ЮMoney, Сбер) → клиент подаёт заявку (**в первый день проекта**) → подключение в настройках → СБП → тестовый платёж → возврат тестового платежа.

E02 касса 54-ФЗ: касса провайдера или облачная (Бизнес.Ру, OrangeData, CloudKassir и т. п.) → ставки НДС в товарах → проверка чека. Риск: ИП на УСН с неверной ставкой НДС с 2025–2026 годов — **проверять с бухгалтером клиента**, мы ставим то, что он подтвердил письменно.

## Доставка (F)

Варианты: штатные приложения служб (F01, по 1 ч за службу) / агрегатор при 3+ службах (F03) / свой курьер и самовывоз (F02). Без веса и габаритов у товаров расчёт не работает — F04 или задача клиенту. Тест: заказ в другой регион, выбор ПВЗ, правильная цена.

## CRM, телефония, опт (G)

- **G04 CRM**: amoCRM, Битрикс24, RetailCRM — через приложения inSales. 2 ч на подключение + 2 ч на настройку полей и воронки за каждую CRM. Риск — дубли контактов и платное приложение.
- **G06 телефония** только вместе с CRM.
- **G07 опт**: тип цен, группа клиентов, кабинет. Минимальные партии и индивидуальные прайсы — уже разработка.

## 1С (H03–H07)

| Шаг | Код | Норматив | Что проверяем |
|---|---|---|---|
| Определить конфигурацию 1С (УТ, УНФ, КА, Розница, самописная), версию, где стоит (облако/сервер) | H03 | 1,5 ч | Типовая ли конфигурация, есть ли обмен с сайтом (CommerceML) |
| Схема обмена: что откуда куда и как часто | H03 | (входит) | Документ на 1 страницу, подписывает клиент |
| Товары и характеристики | H04 | 4 ч | Группы, артикулы, свойства, картинки |
| Остатки и цены | H05 | 2 ч + 1 ч на каждый доп. склад/тип цен | Какой склад виден на сайте |
| Заказы и контрагенты, обратные статусы | H06 | 3 ч | Заказ из inSales → документ в 1С → статус обратно |
| Тест обмена | H07 | 2 ч | Бэкап до первой синхронизации! |

**Граница ответственности:** настройку на стороне 1С делает программист 1С клиента; мы — сторону inSales и тест. Если программиста нет — ищем партнёра-одинэсника, его часы не входят в нашу смету. Нетиповая конфигурация → оценка только после этапа 0.

## МойСклад (H01, H02, H07)

Приложение в inSales → сопоставление по артикулу → какие склады и тип цен выгружать → заказы и статусы → тест. 3 + 1,5 + 2 ч. МойСклад часто сам держит интеграции с WB/Ozon (у него пакетная интеграция с площадками от 3 500 ₽/мес) — тогда **остатки МП синхронизирует МойСклад, а не inSales**. Решаем на этапе 0, чтобы не было двух источников остатков.

## Маркетплейсы (M)

| Шаг | Код | Норматив |
|---|---|---|
| Подключить площадку (тариф с интеграцией или приложение), API-ключ | M01 | 1 ч |
| Сопоставить товары (артикул/баркод) | M01 | 2 ч на площадку |
| Единые остатки | M02 | 1 ч на площадку |
| Заказы площадки в админке | M03 | 1 ч на площадку |
| Правила цен сайт/площадка | M04 | 1 ч |

**FBO** (склад площадки) — остатки площадки не связаны с собственным складом; на сайте продаём только со своего склада. **FBS** — единые остатки работают. Правила площадок о ценах на внешних каналах и о «переводе» покупателей проверяем на каждом проекте и не обещаем механик, которые их нарушают.

> Перед сметой проверить на insales.ru, какой тариф даёт интеграцию с нужной площадкой и сколько стоит приложение. Данных на 07.10.2026 нет (см. 10-improvement.md).

## SEO и перенос (S)

- **S01–S02 в базе**: шаблоны мета-тегов, ЧПУ, sitemap, robots, вебмастера. Трафик это не приносит, только убирает технические ошибки.
- **S03–S04 опция**: семантика и тексты категорий. Эффект через 2–4 месяца.
- **S05–S07 перенос**: выгрузка → карта 301 по всем URL с трафиком (из Вебмастера + краулер) → 4 недели контроля индексации. Без S06 перенос сайта с трафиком **не берём**.

## Аналитика (N)

N01 в базе: счётчик, вебвизор, цели «корзина → оформление → заказ». N02 e-commerce — обязательна, если клиент будет покупать рекламу. N04 дашборд — заказы по источникам, конверсия, средний чек; продаётся как «увидеть, окупается ли канал».

## Тест (T)

T01 — чек-лист из 40 пунктов. Минимум: заказ с телефона и с компьютера; оплата картой и по СБП; возврат; чек пришёл; доставка в другой регион; письмо покупателю и уведомление менеджеру; заказ без регистрации и с регистрацией (известная жалоба на сброс корзины после входа); промокод; 404; форма согласия на обработку ПДн. Чек-лист — в [05-process.md](05-process.md#чек-лист-приёмки-t01).
